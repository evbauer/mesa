TASK051 repeats all original candidate/legacy records from canonical039
(680 scalar trials) and042 (592 coupled trials), through both actual FreeEOS
component and final EOS APIs:2544 model solves. The lead cleared this bounded
consumer gate at18:52 PDT on2026-10-29; it is not stellar clearance.

`run_consumers.py` imports the unchanged solvers by qualified package paths;
no old models.py, source tables, source preprocessing, bridge/client, or
installed libraries are changed. Forcing, previous state, solver start,
brackets/boxes, tolerance and own-model independent-reference algorithms are
retained. The scalar sample-geometry recipe uses the cached native grid;
all original reference sample counts are preserved. New API values replace
only the old table model callback. No forcing is recalibrated.

The lead's serial EOSClient provides the frozen fixed20-isotope component/final
driver. Its exact-query memoization remains intact. Every logical evaluation
is logged with stage, actual-query row, memo flag, status, callback count,
retention flag and all eight returned fractions. Actual pipe commands/results
remain separately available. Accepted/rejected/initial/reference states are
exported separately. Outside-bracket proposals rejected before EOS evaluation
are explicitly unqueried; their routing is not invented.

`analyze.py` independently scans the saved125-column protocol. It asserts
successful candidate component calls invoke exactly one callback; successful
candidate final calls invoke exactly one callback for a positive FreeEOS
fraction and none for exactly zero; opt-out calls invoke none. It also checks
fraction validity, every serialized value/partial finite, and the frozen
driver's full27-by20 internal retention/finite flag. The public protocol
contains only40 abundance derivatives, so the internal27-row evidence is the
driver's checked flag, not independently serialized full arrays. The051 paths
contain no inactive FreeEOS samples; the zero-fraction branch has no observed
051 instance. Lead050 has the separately scoped inactive-route test.

`diagnose_precision.py` preserves the two original T0980 failures and adds
explicitly separate neighboring-representable-state, consumer-arithmetic,
cell-arithmetic and tolerance controls. `compare_precision.py` keeps the
polynomial basis, summation order, binary64 nodes, effective API coordinates,
forcing and solver fixed while changing only polynomial arithmetic precision.
These offline controls do not replace the actual-API outcomes and do not
change any runtime/source code. `make_figures.py` plots saved results only.
